# Actions: hard rules

The one-line rule is in `CLAUDE.md`; this is what breaking it looked like.

## actions-rule-1: A caller that changes state calls an action

**A new door that changes app state calls the action for it; a new kind of
change adds an action.** Never the work itself in an IPC handler, a command's
answer, a key or the sweep.

What a second copy cost: a ship, `pane run`, the review loop, New Claude and a
restart each started their agent their own way. Only `pane run` could pick a
Claude screen, so `pane run --screen` gave a screen and a ship of the same card
gave a terminal; and a pane that comes back as a plain shell after a restart
still gets `claude --resume` typed into it, with no screen, no worker hooks, and
nothing in the log saying an agent started.

`src/main/actions/bypasses.test.ts` names every call that still does the work
itself and where it is made (`inventory.md`). A new caller fails it. A noun's
card that moves a call behind its action lowers the count in the same change;
raising one is this rule being broken.
